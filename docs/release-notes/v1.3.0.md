## Fix: crash after the Gommage (game 1.5.0)

The randomizer's copies of the game files came from the game before update 1.5.0. That update added a field to the cinematic triggers used by the Expedition Festival dialogues (the evening right after the Gommage). The mod replaced those dialogues with the old files, and the game crashed as soon as the festival loaded. A save made during the festival crashed on load, and one made after the departure loaded fine.

- The game files in the Data folder are updated to game version 1.5.0 (encounters, enemies, items, chests, merchants and the dialogues that changed). Content added in 1.5.0 (Verso's Drafts and the new bosses) isn't randomized and keeps its items.
- The mod now contains only the item files it actually changes. Every other file comes from the game itself, so a future game update can't be broken by an outdated copy of a file the randomizer didn't touch.

## Logging

- **generation_log.txt** is written next to every generated mod. It contains:
  - the randomizer version and the game version its data comes from;
  - the settings and seed;
  - the game's Steam build and the other installed mods (~mods, LogicMods, UE4SS);
  - every game file the mod replaces;
  - the files that were left out because they didn't change;
  - the output of the packer and the files copied into the game.
- **logs\randomizer.log** next to the exe collects the randomizer's own errors with full details.
- **enable_game_crash_dumps.ps1** (next to the exe): the game writes no logs of its own. Run this script once in PowerShell as administrator, and Windows will save a crash dump of every game crash into %LOCALAPPDATA%\CrashDumps\Expedition33.

Generate the mod again with this version and load a save from before the Gommage (or from the festival).

Updating: older versions offer this update on startup.
